## Defects found, with file and line

### D1. Every DEF under-scored by the shutout bonus - FIXED

`draft_board.py:40`. `score()` excluded every stat starting with `pts_` to avoid Sleeper's precomputed 4-point-TD fantasy points. But `pts_allow_0` - a real defensive stat this league pays 10.0 for - starts with `pts_` too, so every defense lost its projected shutout points. Hand validation caught it: 23/25 exact, both DEF rows off by exactly -10.0.

Fix: exclude exactly `pts_ppr`, `pts_half_ppr`, `pts_std` plus the `adp_`/`rank_` prefixes. Re-validated 25/25. **Impact on conclusions: none** - the shutout projection is uniform across defenses, so 0 of 32 DEF change rank order, and QB/RB/WR/TE/K scores are bit-identical before and after.

### D2. The documented 168/168 reconciliation did not reproduce - FIXED

`src/ingest.py:194`. The 2025 archive-vs-Sleeper comparison was lowercase-only. Four picks disagreed on suffix variants (Brian Thomas Jr., Kenneth Walker III, Marvin Harrison Jr., D.J. vs DJ Moore), so the code produced 164/168 while the docs - and the committed `out/phase1_results.json` said 164 while `HANDOFF.md` said 168. Fix: `_norm_player()` strips periods and generational suffixes for comparison only; stored names are never rewritten. Now 168/168 from code.

### D3. `out/lineup_efficiency.csv` had no generator - FIXED

After `313cb2b` removed the writer from `build_app_data.py` (comment at `src/build_app_data.py:69`: owned by phase3_lineup) and PR #3's refactor removed it from `phase3_lineup.py` (docstring said the reverse), **each script pointed at the other and neither wrote the file**. Fix: `phase3_lineup.py` owns it again; the restored writer reproduces the resolved file byte-for-byte; `README.md:33-36` rebuild chain now includes `phase3_lineup.py`.
